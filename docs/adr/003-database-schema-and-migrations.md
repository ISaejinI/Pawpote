
# ADR 003: Database Schema and Migrations

## Status

Accepted

## Context

Pawpote needs a persistent database to manage users, dog
profiles, activities, preferences, swipes, and matches.

The application uses Neon PostgreSQL as its database and
Drizzle ORM for database schema management.

A structured schema is required to ensure data consistency,
enforce relationships, and support future API development.

## Decision

We will define and manage the PostgreSQL schema using
Drizzle ORM and Drizzle Kit.

The database schema is split into two files:

- `src/db/auth-schema.ts`: authentication tables generated
  by Better Auth.
- `src/db/schema.ts`: Pawpote application tables.

The application schema includes:

- Dog breeds, activities, and character traits.
- Owner profiles linked to authenticated users.
- Dog profiles and their photos.
- Many-to-many relationships for activities and traits.
- Likes and dislikes between dogs.
- Matches created after reciprocal likes.

UUIDs are used for dog-related entities, while Better Auth
keeps its generated text-based user identifiers.

Foreign keys, unique indexes, and check constraints enforce
data integrity at the database level.

Database changes are versioned through SQL migrations
generated by Drizzle Kit.

Neon branches separate development and production databases.
Migrations are tested on the development branch first.

## Consequences

### Positive

- Type-safe database schema definitions.
- Version-controlled SQL migrations.
- Referential integrity through foreign keys.
- Prevention of duplicate swipes and matches.
- Clear separation between authentication and application data.
- Database changes can be reviewed before deployment.

### Negative

- Schema changes require new migrations.
- Additional indexes and constraints increase schema complexity.
- Application-level validation is still required for business rules.

## Notes

The Hono API will enforce business rules that cannot be
guaranteed by the current database constraints alone.

These include:

- Ensuring users can only act on their own dog profiles.
- Preventing swipes between dogs belonging to the same owner.
- Creating matches only after reciprocal likes.
- Handling concurrent match creation safely.
